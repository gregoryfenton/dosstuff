# VGA Raster Interrupt Experiment

An experimental DOS VGA raster-effects project exploring a programmable scanline interrupt mechanism.

The project began with a simple question:

> Can an interrupt be tied directly to the VGA raster position, so that DOS software can execute code at a particular scanline?

In the current environment, DOSBox provides the mechanism needed to experiment with this idea.

The result is a remarkably useful primitive: software can request an interrupt at a particular raster scanline, execute a small interrupt handler, modify the VGA state, and immediately schedule the next scanline.

This makes it possible to create raster effects normally associated with much more specialised graphics hardware.

## The basic idea

The experimental environment provides a synthetic raster interface through port `62h`.

A target scanline is written to the port followed by the interrupt vector:

    low byte
    high byte
    vector 60h

For example:

    target scanline = 137
    interrupt vector = 60h

The emulator then generates:

    INT 60h

when the display reaches the requested raster position.

The interrupt handler performs its raster operation and programs the next scanline.

Conceptually:

    DOS program
        |
        v
    port 62h
        |
        v
    target scanline
        |
        v
    VGA raster reaches target
        |
        v
    INT 60h
        |
        v
    Raster ISR
        |
        +----> modify VGA state
        |
        +----> arm next scanline
        |
        v
       IRET

The important part is that the interrupt is synchronised to the raster rather than being generated by the normal DOS timer.

## Current experiment

The current program is `TINYRAIN.ASM`.

It is a normal `.COM` program rather than a TSR.

It:

1. Saves the existing `INT 60h` vector.
2. Sets VGA text mode `03h`.
3. Builds a 400-line RGB rainbow lookup table.
4. Installs the raster interrupt handler.
5. Arms raster scanline 1.
6. Changes VGA DAC register 7 once per raster scanline.
7. Advances the raster target to the next scanline.
8. Scrolls the rainbow vertically.
9. Prints occasional debug information.
10. Disables the raster mechanism on exit.
11. Restores the original `INT 60h` vector.
12. Restores the normal VGA text colour.
13. Returns cleanly to DOS.

## The rainbow effect

The VGA text screen remains ordinary text mode.

The text itself is not rewritten for every colour change.

Instead, the program changes VGA DAC colour register 7.

The normal text attribute:

    07h

uses palette entry 7 for the foreground colour.

Therefore changing DAC entry 7 changes the visible colour of all text using that attribute without modifying the text buffer.

The raster ISR performs:

    scanline
        |
        v
    rainbow LUT
        |
        v
    RGB value
        |
        v
    VGA DAC register 7

The LUT contains 400 RGB entries covering:

    RED
      |
      v
    YELLOW
      |
      v
    GREEN
      |
      v
    CYAN
      |
      v
    BLUE
      |
      v
    MAGENTA
      |
      v
    RED

The colour therefore changes continuously down the display.

## Scrolling the rainbow

A static rainbow is interesting, but the raster interrupt makes it possible to move the rainbow as well.

The program maintains:

    RainbowOffset

The LUT lookup is effectively:

    LUT index = scanline - RainbowOffset

with the result wrapped around the 400-entry table.

The offset is advanced once per complete raster frame.

Consequently the colour pattern moves down the display rather than remaining fixed.

The display is therefore continuously doing two things simultaneously:

    scanline
        |
        +--> select physical raster position
        |
        +--> select moving position in colour LUT
        |
        v
    DAC colour

No text memory needs to be rewritten.

## Why INT 60h is interesting

The particularly interesting property of this experiment is not the rainbow itself.

It is the relationship between the interrupt and the raster.

A normal DOS timer interrupt tells the program approximately when some amount of time has passed.

The experimental raster interrupt tells the program:

    the display has reached this scanline

That distinction is extremely useful for graphics effects.

The interrupt handler can therefore perform operations such as:

- changing palette entries
- changing border colour
- changing other VGA registers
- creating horizontal colour bands
- producing copper-style effects
- synchronising software with the display beam

The emulator effectively provides a programmable raster event mechanism to DOS software.

## Debugging

The program deliberately remains a normal foreground `.COM` program during development.

This makes it possible to print diagnostic information and verify that the interrupt mechanism is behaving correctly before turning the code into a TSR.

Debug output is generated every 4000 raster interrupts.

With 400 raster interrupts per frame, this corresponds to:

    400 interrupts / frame
    10 frames / debug message
    4000 interrupts / debug message

Typical diagnostic information includes:

    IRQ count
    frame count
    current scanline
    rainbow offset

This was particularly useful when establishing that the synthetic interrupt was actually being generated at the expected raster positions.

## Source structure

The core experiment is deliberately small.

The important components are:

    START
        program initialisation and shutdown

    CommitRasterTarget
        programs the next raster target

    RasterISR
        performs one raster operation

    BuildLUT
        constructs the RGB rainbow lookup table

    PrintString
        DOS debug output

    PrintHexWord
        hexadecimal diagnostic output

The raster handler is the central part of the experiment.

## Raster ISR

The essential operation is:

    RasterISR
        |
        +-- save registers
        |
        +-- increment raster counter
        |
        +-- determine current scanline
        |
        +-- apply RainbowOffset
        |
        +-- obtain RGB value from LUT
        |
        +-- write VGA DAC register 7
        |
        +-- advance scanline
        |
        +-- detect frame boundary
        |
        +-- advance rainbow offset
        |
        +-- program next raster target
        |
        +-- restore registers
        |
        +-- IRET

The ISR intentionally does not perform DOS calls.

This keeps the raster handler small and avoids entering DOS services from interrupt context.

## What has been demonstrated

The experiment has progressed through several stages.

### Interrupt operation

The first tests established that:

- `INT 60h` can be generated by the raster mechanism.
- The ISR executes repeatedly.
- The scanline target advances correctly.
- The raster wraps back to the beginning of the frame.
- Foreground DOS execution continues after `IRET`.

### DAC control

The next test changed DAC register 7 to a fixed colour from the raster ISR.

This demonstrated that the VGA palette can be modified at raster time.

### Multiple colours

The DAC was then changed through several discrete colours:

    RED
    GREEN
    BLUE
    WHITE

This demonstrated that the colour can change independently at each raster position.

### Continuous rainbow

The discrete colours were replaced with a 400-entry RGB lookup table.

The result is a continuous rainbow covering the raster.

### Moving rainbow

Finally, a frame-dependent LUT offset was introduced.

The rainbow now moves vertically through the text rather than remaining stationary.

This is the current experiment.

## Why this matters

This project is not primarily a text-mode graphics project.

The text-mode rainbow is simply a convenient and very visible demonstration of a more interesting capability:

    software-controlled raster interrupts

Once an interrupt can be synchronised to the display beam, a DOS program gains a primitive similar in spirit to the raster/copper techniques used by dedicated graphics systems.

The VGA hardware remains responsible for generating the actual picture.

The CPU simply changes selected VGA state at precisely controlled raster positions.

## Future work

The immediate software work is to explore what other VGA effects can be driven from the raster interrupt.

Possible experiments include:

- multiple palette changes within one frame
- copper-style colour bars
- animated palette effects
- raster-synchronised scrolling
- split-screen effects
- changing VGA registers at selected scanlines
- programmable raster event tables
- multiple raster events per frame
- TSR implementation
- QBX/PDS callable raster routines
- integration with existing DOS graphics programs

A longer-term experiment would be to determine whether the same software model can be reproduced on physical VGA hardware.

## Real hardware investigation

The current raster interrupt mechanism is an emulator feature and is not assumed to exist on standard VGA hardware.

However, the underlying timing signal does exist physically.

VGA provides horizontal and vertical synchronisation signals.

A possible future hardware project would tap HSYNC and VSYNC and use them to generate an equivalent programmable interrupt for an ISA-based DOS machine.

The important distinction is that this is a future hardware experiment.

The current repository is primarily concerned with understanding and exploiting the raster interrupt mechanism from DOS software.

## Status

Experimental.

The current proof of concept successfully demonstrates:

    VGA text mode
        +
    scanline-synchronised INT 60h
        +
    per-scanline DAC updates
        +
    400-entry RGB LUT
        +
    vertically scrolling rainbow

The result is a surprisingly effective VGA raster effect running entirely from a DOS `.COM` program.

And, perhaps most importantly, it demonstrates that an apparently ordinary software interrupt can become something much more interesting when it is tied directly to the display raster.
